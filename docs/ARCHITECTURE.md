# 技术架构与关键取舍

[返回项目首页](../README.md) · [开发过程](PROCESS.md)

## 当前在线架构

```text
GitHub main 分支 → GitHub Pages 构建/发布 → HTTPS 静态文件
                                            ↓
                         轻量HTML加载提示 + JS/CSS + WebP
                                            ↓
                                  浏览器内的 React 应用
                          首页 → 问卷状态 → 规则评分 → 结果
                                                       ↓
                                              Canvas → PNG
```

运行时不需要数据库、不调用大模型，也没有结果分析API。浏览器通过localStorage尝试保存会话；文档重新加载时回首页并清理本次会话，页面内切换则保留答题流程。不可把这一机制描述为账户系统、云端同步或跨设备恢复。

## 原始工程与线上成品的区别

| 层次 | 使用的技术 | 说明 |
| --- | --- | --- |
| 原始开发工程 | React、Next.js、TypeScript | 有问卷、结果、分享及后端探索代码，保留在本地工程 |
| 静态构建入口 | Vite | 复用前端组件，为导航、图片路径、分享面板提供静态适配 |
| 展示与交互 | CSS Modules、SVG、CSS animation | 保持Neo-Brutalism视觉；动态效果有暂停与减少动态效果模式 |
| 结果图片 | Canvas、Blob URL | 浏览器生成1080×1080或1080×1440 PNG |
| 测试工具 | Vitest、Testing Library、Playwright | 测试源码不在当前公开成品仓库 |
| 发布 | Git、GitHub Pages | main根目录作为发布源，保留提交历史用于回退 |

这里没有将“Next.js开发工程”称为“Vite原生开发的完整项目”，也没有让GitHub Pages执行Next.js服务端。

## 评分逻辑的边界

主测32题，每个E/I、S/N、T/F、J/P维度各8题。选项按题目正反向映射到3、1、-1、-3或反序；每维总分范围为-24至24。结果映射出类型，同时提供倾向百分比及balanced/slight/clear/extreme四档强弱。

百分比是按规则从分数转换的显示值，不是概率、置信度或“测量准确率”。零分在当前代码中使用确定性字母回退，同时可呈现均衡倾向；四字母标签不能完整表达场景变化。

隐藏面另有8道题和社交、关系、工作、内耗四个评分方向，按规则组合生成娱乐性隐藏画像。它不是临床量表，也没有经过信效度验证。

## ADR-001：先部署静态体验，不部署后端

**状态：采用。** 背景是用户明确希望先让作品可公开体验，而暂不处理后端。

决定：复用现有前端代码生成静态网站；图片卡在本地生成，网站链接指向首页。

取舍：可以演示测试与分享交互，不需要服务端运行费用或数据库配置；但个人结果链接、撤回记录、长期存储、跨设备同步和后台分析不可用。本地后端探索不等于生产能力。

## ADR-002：在线版拆包，单文件版只作独立产物

**状态：采用，替代最初的全量单HTML在线发布方式。** 初版将约8.24 MiB内容放在一个HTML里，真实手机出现白屏反馈。

决定：在线入口只保留基础HTML和启动提示，引用独立脚本、样式和优化后的WebP；离线版继续内嵌素材，单独保存。

取舍：入口不再等待全部图像数据，资源可独立缓存；增加了资源请求数，仍受访问GitHub Pages的网络状况影响。拆包不是保证所有设备可用的充分条件。

启动错误提示使用固定编号L01–L05，不收集或上传用户答案与运行错误详情。原始素材不因在线压缩而被覆盖。

## ADR-003：图片分享优先于服务端结果链接

**状态：采用。** 当前分享链路为生成PNG、用户下载/长按保存，以及复制网站链接邀请朋友测试。

取舍：无需后端公开个人结果；分享后的图片无法撤回，网页也无法保证自动保存到相册。系统分享菜单与跨浏览器保存体验属于后续优化，不在当前完成清单。

## 可维护性与复现范围

本仓库可复现静态网站的运行，但没有原始组件和测试源码，因此不能从这里重建整个开发工程。本文中的源模块名只用于说明本地原始工程的职责：问卷与评分、结果选择、角色展示、分享卡渲染、静态导航适配。

后续若决定公开源码，应另行检查依赖锁定、许可证、素材来源、环境文件与私有资料，再提供最小可复现的构建和测试命令。当前不编造本仓库不存在的 `npm run build` 指令。
