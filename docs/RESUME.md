## 一分钟项目介绍

这是一个用Codex协作完成的娱乐人格测试项目。我主要负责产品方向、功能取舍、视觉要求和体验验收，AI辅助具体实现与测试。它有32道主测和8道自愿加测，用户做完主测就能保存人格卡，不需要先把全部题答完。

最值得讲的是上线后的迭代：最初为了做成单HTML，把图片都嵌了进去，手机反馈白屏。后来改成轻量入口和独立压缩图片，并补了加载失败提示与WebKit测试。另一个例子是题库：用户指出题意不搭和场景重复后，没有只改几个词，而是换成了明确的熟人散步场景。

目前已经公开上线，但仍是静态MVP，没有用户增长数据、服务端分析或经过心理学验证的测评结论。

## 面试追问准备

### 1. 哪些是你做的，哪些是AI做的？

人工负责定位、优先级、参考风格选择、题目语义反馈、结果验收与发布决策；Codex协助方案细化、代码、测试和部署。用具体决策举例，不把AI生成的工作全部说成独立手写。

### 2. 为什么选Vibe Coding？

项目用来实践如何通过自然语言需求和可验证反馈推动产品落地。没有人工对照项目或完整计时记录，因此不能声称“效率提升X倍”。重点是迭代机制、范围管理和验收质量。

### 3. 有什么业务结果？

目前的成果是可访问的产品、完整核心流程和明确的工程产物改进，不是已经验证的传播增长。没有用户量、留存或转化率统计，下一步才是定义合适的事件与指标。

### 4. 为什么先不部署后端？

按当前阶段优先交付可体验作品。评分和PNG都能在浏览器完成，GitHub Pages足够展示核心价值。代价是不能提供持久化个人结果链接和服务端数据分析。

### 5. 最大失误是什么？

把单文件在桌面/模拟环境能打开，过早等同于手机可用；以及第一次修题干没有同时检查与其他题目的重合。改进是明确验收环境，检查整组题而非孤立措辞，并在文档里保留未验证项。

### 6. 这个测试准确吗？

它是娱乐性规则测试，没有心理测量信效度验证。自动化测试验证的是题库结构、得分计算与界面行为，不证明人格结论准确。

## 不应写进简历的表述

- “获得大量用户、自传播增长、提升转化率”：没有对应数据。
- “独立手写全栈应用 / 大模型实时人格分析”：与协作方式及运行架构不符。
- “后端与数据看板已上线”：当前公开版没有这些能力。
- “全站2KB / 加载速度提升99%”：混淆入口HTML、总资源体积和加载耗时。
- “已适配所有手机 / 自动保存相册”：现有证据不足且能力不符。
- “心理学准确率达到XX%”：没有验证依据。
